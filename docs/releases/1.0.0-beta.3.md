# OpenTake 1.0.0-beta.3

发布日期：2026-08-09（Asia/Shanghai）

## Beta 目标

在 `1.0.0-beta.2` 的安全与交互门禁基础上，修复两个直接影响素材预览的高优先级问题：
全局空格播放/暂停失效，以及部分 HEVC（包括 Main 10、10-bit 4K）素材在 WebView 直接解码时
出现黑屏、解码异常或底部绿色画面。同时修复 Beta 2 发布阶段对源码树洁净度的破坏，确保同一
exact-SHA 候选能够完整走完构建、校验和 prerelease 发布。

## 主要变化

- App 内的非文本编辑区域统一由全局 transport 处理空格键：素材卡片、预览、Inspector、
  Timeline 与 Agent 面板获得焦点时均可播放或暂停；输入框和文本编辑控件保留正常的空格输入。
- 单素材视频预览的正常路径改走 Rust 原生 FFmpeg 流式播放，不再依赖 WebKit `<video>` 对
  原文件的 codec/profile 支持；播放、暂停、切换素材和暂停态精确 seek 绑定到当前素材会话，
  仅在原生能力不可用时保留 WebKit fallback。
- HEVC Main 10 / `yuv420p10le` 4K 素材通过原生解码、RGBA 帧缓冲和同一预览控制面输出，避免
  WebView 解码差异造成的黑屏、绿色底边和异常帧；媒体错误仍显式上报，不静默伪装成功。
- 全局空格键路径增加媒体卡片与各编辑面板的回归矩阵；原生源预览增加会话切换、暂停 seek、
  终止状态及真实 HEVC Main 10 像素 probe 覆盖。
- publish job 设置 `PYTHONDONTWRITEBYTECODE=1`，防止发布辅助脚本在 checkout 内生成
  `scripts/__pycache__`，从而触发 exact-source clean-tree 门禁；release contract 包含对应突变测试。
- 应用、Cargo workspace 与 Web 包版本统一为 `1.0.0-beta.3`；Windows MSI 的数值安装器版本
  固定为 `1.0.0.3`，并由发布合约 fail closed 校验。

Beta 2 的 `v1.0.0-beta.2` tag 保持不可移动。Beta 3 使用新的 `v1.0.0-beta.3` tag，不通过
重写旧 tag 或旧 Release 来替代失败候选。

## 候选包验收顺序

同一候选包必须严格执行：

1. Home / 工程生命周期与恢复。
2. 素材库、文件夹、收藏、缩略图、波形、代理与重链接。
3. 选中 H.264、HEVC Main 和 HEVC Main 10 素材，分别验证播放、暂停、seek、连续帧与切换素材。
4. 素材卡片、预览、Inspector、Timeline 与 Agent 面板逐一聚焦后验证空格播放/暂停；文本输入空格
   不得误触 transport。
5. 时间线选择、拖放、裁剪、分割、复制、链接、吸附、撤销/重做与嵌套序列。
6. 时间线预览、seek、scrub、A/V 同步、Transform/Crop/Mask 与关键帧。
7. 文本/字幕、转写、翻译、SRT/VTT、特效、调色、音频处理和样式。
8. Agent/MCP、官方 Codex / ChatGPT 登录与一次真实可撤销编辑；无凭据云功能 fail closed。
9. Motion Canvas、保存重开和 H.264/H.265/ProRes 最终导出。
10. 完全退出 App，重新启动并重开工程，复验两个播放入口和最终输出。

代码测试不能替代 GUI 观察；GUI 观察也不能替代媒体 probe、工程重开和最终输出解析。

## 外部边界

- 未获得 provider key 和明确费用授权时，不执行真实付费生成、翻译、数字人或音色克隆请求；
  只验证同意/费用门禁和无凭据拒绝。
- 本地 macOS 包为 ad-hoc Beta，不宣称 Developer ID 签名或 Apple 公证。
- 原生 Windows Job Object、reparse-point、安装和 WebView 交互必须由 exact-SHA Windows CI / 实机
  验证；macOS 结果不能代替。
- 固定端口、无认证的外部 MCP 在本 Beta 关闭；Claude、Cursor 等客户端等待安全配对流程。

## GitHub 自动发布流程

`.github/workflows/release.yml` 只接受 `v*` tag push；人工 `workflow_dispatch` 只能输入一个
已存在的同名 tag，用于失败运行的重试。流水线不创建、不移动 tag。发布前必须在流水线外将
`v1.0.0-beta.3` 标记到远端 `main` 的当前 HEAD，再 push 该 tag。

每次运行依次 fail closed 执行：

1. 将 `v<semver>` tag 解析为不可变 source SHA，核对 tag 目标、远端 `main` 当前 HEAD、
   Cargo/Tauri/Web 版本、Windows MSI `1.0.0.3` 安装器版本和本文档；Beta 3 必须是 prerelease。
2. Ubuntu 运行依赖锁定安装、audit、license、test、可复现构建，Windows/release 工作流合约、
   sidecar provisioner、Rust fmt/clippy/workspace tests 和 Web test/build 门禁。
3. `macos-14` ARM64 对 exact SHA 使用 checksum-pinned FFmpeg sidecar 构建 `.app` + `.dmg`，
   执行 strict codesign、DMG verify/挂载复验和媒体 smoke；产物仅为 ad-hoc 签名。
4. `windows-2022` x64 对 exact SHA 构建唯一 MSI 和 NSIS，静默安装 NSIS，对安装后程序做启动
   smoke，并在无 PATH 依赖的安装目录边界执行 sidecar probe/decode/encode smoke。
5. 两个平台 receipt 绑定 source SHA、文件字节数与 SHA-256；`SHA256SUMS` 精确覆盖 DMG、MSI、
   NSIS 和两个 receipt。
6. publish job 在创建/刷新 draft 前和公开前都重新解析远端 lightweight/annotated tag，并要求
   peeled commit 与 source SHA 完全一致；Python 辅助脚本禁止向 checkout 写入 bytecode。
7. 只在所有门禁成功后创建 draft prerelease，上传严格计数的六个资产；GraphQL 核对
   tag/commit/assets 后以 `latest=false` 公开，最后下载回读并复验资产和 checksum。

workflow 顶层权限是 `contents: read`，只有 publish job 提升为 `contents: write`；所有外部
GitHub Actions 固定到 40-hex commit SHA。同 tag draft 只允许失败重跑刷新；同 tag 一旦公开，
任何重跑都必须拒绝修改。

## 回滚

- 使用独立 prerelease 标签 `v1.0.0-beta.3`；不移动或复用 `v1.0.0-beta.1`、
  `v1.0.0-beta.2` 或正式版标签。
- 发布资产附 SHA-256；回滚前先复制 `.opentake` 工程包，避免旧版本保存时忽略新增字段。
- 如 Beta 3 公开后发现回归，保留 Beta 3 tag 和资产作为审计记录，用户回退到上一份已验证的
  已公开版本；修复通过全部门禁后使用更高的新 prerelease 版本发布。
- `v1.0.0-beta.3` 一旦公开，不能通过 dispatch 重写。
